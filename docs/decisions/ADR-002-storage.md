# ADR-002 — 저장 구조와 단일 진실 원천

- **상태:** Accepted
- **날짜:** 2026-08-03
- **결정자:** Claude (Architect) / Human 승인 완료
- **관련:** [ADR-001](ADR-001-language.md), [architecture.md](../architecture.md) §3

---

## 맥락

초기 논의에서 세 가지 저장 방식이 동시에 거론됐다.

- **SQLite** — 상태·큐·이벤트의 트랜잭션 저장소
- **`state.json`** — 사람이 읽는 현재 상태
- **Git-tracked 문서** — Task, Report, Review, Memory

세 곳에 같은 사실의 사본이 존재하면 **반드시 어긋난다.**
그리고 어긋났을 때 무엇이 옳은지 판단할 규칙이 없었다.

BCOS의 존재 이유는 "여러 에이전트가 하나의 상태를 공유한다"는 것이다.
상태가 셋으로 갈라지면 프로젝트 자체가 무의미해진다.

## 각 방식의 성질

| | Git 머지 | 사람이 읽기 | 동시 쓰기 | 쿼리 |
|---|---|---|---|---|
| Git-tracked `.md` | 가능 (충돌 해결 가능) | 최적 | 충돌 나지만 복구 가능 | 불가 |
| `state.json` | 가능하나 잦은 충돌 | 가능 | 위험 | 약함 |
| **SQLite** | **불가 (바이너리)** | 불가 | 강함 | 강함 |

**SQLite의 문제가 결정적이다.** 저장소를 클론해 브랜치 두 개에서 작업하는 순간,
`.sqlite` 파일은 Git이 머지할 수 없는 바이너리 충돌을 낸다. 수동 복구도 불가능하다.

이는 BCOS가 해결하려는 문제(P2: 공유 진실 원천의 부재)를 **더 악화시킨다.**

## 결정

### 1. Task의 단일 진실 원천은 `.bcos/tasks/*.md`다

Markdown + YAML frontmatter. 사람이 읽고, Git이 머지하고, 에이전트가 파싱한다.

### 2. `.bcos/events.jsonl`은 append-only 감사 로그다

한 줄에 이벤트 하나(JSON Lines). **수정·삭제하지 않는다.**

라인 단위이므로 Git 머지가 안전하다. 두 브랜치가 각각 이벤트를 추가하면
머지 결과는 두 이벤트가 모두 남은 상태가 되며, 이것이 감사 로그로서 올바른 동작이다.

### 3. `.bcos/state.json`은 파생 인덱스다

Task 파일과 Event로부터 **언제든 재생성 가능해야 한다.**

```bash
bcos reindex
```

`state.json`이 삭제되거나, 손상되거나, Git 충돌을 내면 **그냥 버리고 재생성한다.**
머지 충돌을 손으로 푸는 파일이 아니다.

### 4. 충돌 시 우선순위

```
tasks/*.md  >  events.jsonl  >  state.json
```

셋이 어긋나면 항상 왼쪽이 이긴다. `state.json`은 절대 근거가 되지 못한다.

### 5. SQLite를 v0.1에 넣지 않는다

`cache.sqlite`, `.bcos/db/`, 그 밖의 어떤 데이터베이스 파일도 만들지 않는다.
**미래를 위한 빈 디렉터리나 추상화 계층도 미리 만들지 않는다.**

## 확정 구조

```
.bcos/
├── tasks/          # 진실 원천 — Claude 소유
├── reports/        # 사실 기록 — Codex 소유
├── reviews/        # 판정 — Claude 소유
├── events.jsonl    # append-only 감사 로그
└── state.json      # 파생 인덱스 (재생성 가능)
```

## 근거

- **P2 해결이 최우선이다.** 상태를 나누는 어떤 최적화도 이 목표보다 앞설 수 없다.
- **v0.1 규모에서 쿼리 성능은 문제가 아니다.** Task가 수천 개가 되기 전까지
  파일 스캔은 밀리초 단위다. SQLite의 유일한 장점이 발동하지 않는다.
- **Windows 파일 락 문제를 통째로 회피한다.** SQLite WAL은 동기화 폴더에서 깨진다.
- **재생성 가능성이 백업을 대체한다.** `state.json`이 깨져도 잃는 것이 없다.

## 결과

**긍정**
- Git이 유일한 동기화 메커니즘이 된다. 별도 마이그레이션·백업·복구 절차가 필요 없다.
- 사람이 모든 상태를 텍스트 에디터로 읽고 고칠 수 있다. 최후의 탈출구가 항상 열려 있다.
- 구현 언어를 바꿔도 데이터가 살아남는다 ([ADR-001](ADR-001-language.md)의 되돌리기 비용을 낮춘다).

**부정 (수용함)**
- Task가 수천 개가 되면 `task list`가 느려진다.
  → 그 시점에 `.gitignore`된 캐시를 도입한다. **캐시는 진실 원천이 아니므로 이 ADR을 뒤집지 않는다.**
- 복잡한 쿼리(의존성 그래프 탐색 등)를 못 한다.
  → v0.1에 그런 요구가 없다. 생기면 그때 다시 결정한다.

**되돌리는 조건**
- Task 1,000개 이상에서 `bcos status`가 1초를 넘으면 읽기 전용 캐시를 도입한다.
- **단, `tasks/*.md`가 진실 원천이라는 규칙 자체는 되돌리지 않는다.**
